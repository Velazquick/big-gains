Limited usage and technical information

Big Gains collects limited first-party information to understand product usage and reliability. Signed-in observations include app opens, workout starts and completions, Program activation, exercise Swap use, recovery actions and application diagnostics. They include release, coarse platform/browser type and browser or standalone mode.

Diagnostics contain only allowlisted technical categories, application-defined codes, known application module names, lifecycle stages, error classes and a stable code made from those bounded values. Unknown failures remain unknown. Conflict observations use a random episode identity for a continuous unresolved interval in one tab/profile/channel. It survives reloads in that tab; another device or tab may have its own episode. It is not a globally unique count of underlying problems.

Training weights, repetitions, bodyweight, exercise names, private notes, raw error messages, raw stack traces, arbitrary URLs, tokens, headers and serialized application state are not included. We do not use session replay, advertising IDs, IP-derived identity, cross-site tracking or browser fingerprinting.

Before sign-in, a separate write-only path observes visits, signup-screen reach and signup attempts. It uses a random session identifier lasting at most 30 minutes in the current tab, coarse platform/browser/mode and only the campaign values direct, beta-wave-1 or beta-wave-2. It does not collect email, Auth identity or referrer URLs. These sessions are not unique people and are not linked to accounts for conversion claims.

Authenticated telemetry is associated with the signed-in account and selected profile. Only the authorized owner's read-only Operator Console can inspect account identity, confirmation status, aggregate workout counts/dates, Program adoption and operational observations. It cannot read complete workouts or training contents through these queries. Public observations are shown only as aggregates.

Telemetry is best effort: observations can be dropped when offline, rate-limited or unavailable. Telemetry is never required for training, recovery, synchronization or signup and has no persistent delivery queue. Public observations are retained for 30 days; authenticated events for 90 days, with daily cleanup normally adding at most one day. Deleting the associated account, profile or Auth database record cascades its authenticated events. Administrative soft deletion does not immediately remove events. First observed authenticated app-open date is retained until account deletion for return cohorts. Product data storage and backups are separate.
